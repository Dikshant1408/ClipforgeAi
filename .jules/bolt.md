## 2024-05-14 - Optimize audio energy calculations
**Learning:** Audio processing often involves overlapping sliding windows. The original `make_wav_energy_func` opened the WAV file, seeked, read, buffered into a numpy array, squared, and summed it for EVERY candidate window in `highlights.py`. For dense candidate windows, this repeatedly reads and processes the same audio frames from disk, resulting in O(N*W) time complexity where N is the number of windows and W is the window size.
**Action:** Implemented chunk-based LRU caching combined with O(1) interval sums via `np.cumsum(samples.astype(np.float64)**2)`. Note the `.astype(np.float64)` is critical; using `float32` for cumulative sums of squared audio samples results in severe precision loss on large chunks. The chunk caching ensures we only read and square the audio from disk once per 60s block, reducing runtime for dense overlapping queries by ~10x.
