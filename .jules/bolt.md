## 2024-05-14 - Optimize Audio Chunk Energy Computation with Cumulative Sum and LRU Cache
**Learning:** In Python, repetitive file I/O or naive array slicing inside tight loops (like querying many overlapping sliding audio windows for RMS energy) is a massive bottleneck. The overhead of repeatedly decoding the same parts of an audio file and slicing/squaring `float32` arrays in Python is too high. A cumulative sum (`np.cumsum`) allows querying any slice's energy in O(1) time. However, using `float32` for `np.cumsum` on large arrays leads to severe precision loss. Additionally, multi-channel 1D audio arrays read by `wave` must have their logical sample boundaries multiplied by `nchannels` to prevent frame misalignment.
**Action:** When implementing overlapping window computations over large media arrays, read chunks once and use `functools.lru_cache()`. Pre-calculate integral metrics (like cumulative sum of squares) in `np.float64` precision for O(1) interval queries. Ensure proper `nchannels` multiplier indexing when handling flattened multi-channel data.
