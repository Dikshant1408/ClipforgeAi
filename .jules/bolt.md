## 2024-05-24 - O(1) Audio Energy Calculation
**Learning:** In `clipforge/highlights.py`, `make_wav_energy_func` was repeatedly reading frames from the `.wav` file on disk using `wave.readframes()` for every candidate window during highlight detection. With 1000s of candidate windows, this caused a massive bottleneck (taking ~22s for 10 minutes of audio).
**Action:** Instead of reading from disk on every query, read the entire `.wav` file into memory ONCE during initialization and compute a cumulative sum array of squared sample values (`cumsum`). This reduces the energy calculation for any `[start, end]` window from O(N) disk reads to O(1) memory accesses, reducing compute time by 10x+. Always precompute cumulative sums for repeated range query aggregations on static arrays.
